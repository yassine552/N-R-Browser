# Windows Build Guide (docs/WINDOWS_BUILD.md)

NØR Browser supports Windows 10 and 11 through the same C++17 / Qt 6.8 /
CMake code base. **This guide was not executed in the development
environment (Linux-only toolchain there), so treat it as a precise
recipe to verify on your machine.** The Linux CI proves the source is
Qt-API-correct for 6.8; the Windows-specific parts are standard Qt
deployment steps.

> **Ad-block backend note:** the default `Rust` backend needs the Rust
> toolchain on Windows too (rustup offers a standard Windows installer;
`MSVC` ABI). Build with `-DNOR_ADBLOCK_BACKEND=BuiltIn` to skip it —
everything else works identically. The Rust path itself was NOT built
or tested on Windows by the maintainers; no Windows claim is made for
it.

## 1. Install the tools

1. **Visual Studio 2022** (Community is fine) with the *Desktop
   development with C++* workload — includes MSVC v143 and Windows SDK.
   MinGW 13+ from the Qt installer also works.
2. **Qt 6.8.x** via the Qt Online Installer → Qt 6.8.x →
   `MSVC 2022 64-bit`, with components:
   - Qt WebEngine (Additional Libraries → Qt WebEngine)
   - Qt Linguist (Tools → Qt Linguist)
3. **CMake 3.21+** and **Ninja** (both bundled with the installer; or
   use Visual Studio's CMake integration).

## 2. Configure and build

From a *Developer Command Prompt* (or the Qt command prompt):

```bat
cd nor-browser
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release ^
      -DCMAKE_PREFIX_PATH="C:/Qt/6.8.2/msvc2022_64"
cmake --build build -j

:: unit tests
ctest --test-dir build --output-on-failure

:: run
build\nor-browser.exe
```

The Windows-specific bits are already wired in `CMakeLists.txt`:
`WIN32_EXECUTABLE` (no console window) and the version/icon resource
`packaging/windows/nor-browser.rc` (references
`packaging/windows/nor-browser.ico`, which is generated by
`scripts/gen_app_icons.py` and already present in the source tree).

## 3. Deploy the Qt runtime

```bat
cd build
C:\Qt\6.8.2\msvc2022_64\bin\windeployqt --release --compiler-runtime ^
    --qmldir . nor-browser.exe
```

`windeployqt` copies the Qt DLLs, the **WebEngine resources**
(`QtWebEngineProcess.exe`, `resources/`, `locales/`), and the platform
plugins. Additionally copy Qt Linguist files for your UI languages so
standard dialogs are translated too:

```bat
copy C:\Qt\6.8.2\msvc2022_64\translations\qtbase_ar.qm  translations\
copy C:\Qt\6.8.2\msvc2022_64\translations\qtbase_fr.qm  translations\
```

(The application's own `nor-browser_ar.qm` / `nor-browser_fr.qm` are
embedded in the executable and need no deployment.)

## 4. Package

An installer-free zip is usually enough:

```bat
mkdir nor-browser-win64
copy build\nor-browser.exe nor-browser-win64\
xcopy /E /I build\translations nor-browser-win64\translations
:: ... plus everything windeployqt placed next to the .exe
powershell Compress-Archive nor-browser-win64 NOR-Browser-1.0.0-win64.zip
```

For a classic installer, wrap the folder in **Inno Setup** or
**NSIS** (not included here). MSVC builds need the VC++ redistributable
(2015-2022, x64) on the target machine, or link statically with
`/MT`.

## 5. Notes and caveats

- Qt WebEngine on Windows requires **Visual C++ Redistributable**
  (unless static) and supports Windows 10 1809+.
- Do not mix MSVC and MinGW Qt builds with a different compiler —
  Linux Qt binaries cannot be reused on Windows (and vice versa).
- The `nor://` scheme, the off-the-record private profile, SQLite
  storage paths (`%LOCALAPPDATA%\nor-browser`) and all privacy
  features behave identically on Windows; only the OS-open action for
  downloads (`QDesktopServices`) and the desktop integration differ.
- Smoke tests that need Xvfb are Linux-specific; on Windows run the
  unit tests (`ctest`) and launch the browser manually against
  `python tests/scripts/testserver.py` (any Python 3).
