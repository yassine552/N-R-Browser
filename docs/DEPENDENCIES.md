# Dependencies and Licenses (docs/DEPENDENCIES.md)

NØR Browser is deliberately thin: one framework, one database engine,
and (optionally, by default) one native ad-blocking engine — no
third-party application libraries beyond that.

The full redistributable-license inventory, including every transitive
Rust dependency resolved by Cargo, lives in **`THIRD_PARTY_NOTICES.md`**
(generated by `scripts/gen_third_party_notices.py` from
`adblock-sys/Cargo.lock`).

## System runtime libraries (Linux)

Provided by the distribution: `libnss3`, `libnspr4`, `libasound2`,
`libxkbcommon`, `libxkbcommon-x11`, `libxcb-*`, `libX11`, `libGL`/`libEGL`
(glvnd), `libgbm`, `libdrm`, `libcups`, `libatspi`, `libdbus`,
`libfontconfig`, `libfreetype`, `libharfbuzz`, `libicu` (via Qt),
`libxml2`, `libzstd`/`libz`. All are standard LGPL/BSD/MIT-licensed
distribution components.

## License of NØR Browser itself

MIT (see `LICENSE`). Note that *linking* Qt/Qt WebEngine imposes the
obligations of the Qt license you choose (LGPL dynamic linking is the
default mode used by these build instructions). This project's MIT
terms apply to its own source files; they do not relicense Qt or
Chromium.

## Development-environment extras (not part of the shipped app)

The CI container used to develop and test this version also fetched,
without root, into a local toolchain directory: Qt 6.8.2 binaries via
aqtinstall (MIT), CMake/Ninja wheels from PyPI (as above), Pillow
(MIT-CMU) for icon rasterization, and Debian dev/runtime `.deb`s
extracted locally for GL/XKB/XCB/EGL headers. None of these are
required on a normal development machine with Qt installed.
